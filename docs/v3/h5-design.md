## 视觉与内容

- 主视觉：原始招手照 `source/9.1032978.jpg`，搭配专属「我们结婚啦」中文标题。完整保留原片、挥手、脸、花束与裙摆；本轮不需要抠图或人物重绘。
- 关键表达：标题笔势回应招手动作，避免单个普通宋体「囍」与姓名的机械堆叠。
- 配色：暖朱红 `#A93624`、深红 `#852D27`、婚纱白 `#FFF8F0`、墨褐 `#302426`，递花段辅以浅藕粉 `#F1DFD8`、酒红 `#672C35`。保留摄影原色，不给灰底照片染色。
- 字体：标题为已核字的透明图形；姓名、重要日期与段落标题为自托管 Wedding Serif（思源宋体 CN SemiBold 子集）；正文采用设备中文黑体。艺术字不承担地址、厅号和电话。
- 正文：统一用“您”称呼宾客；邀请句为“诚邀您参加我们的婚礼，见证我们成为一家人。”，照片段用“照片里的欢喜”，日程用“这一天，盼您来。”，结尾用“盼与您相聚。”。避免生僻词、仪式套话和虚构恋爱经历。
- 排列：招手开场 → 戒指近景 → 左右错位递花双图 → 灰底吻手 → 集中赴宴信息 → 暖红近景收束。
- 信息区：公历/星期/农历、三项时间及对应场地、酒店完整地址、导航、周边示意图、复制与联系。浅色整版配深红标题与细分隔线，去掉厚重红框和拱形纸张。周边图以 SVG 大图铺满版心宽度，无图注、二次点击、弹层或横向滚动；不冒充酒店内部路线。

```text
招手原片 + 透明中文标题

        ↓

        ↓

        ↓
完整日期 → 三段日程 → 酒店地址 → 导航与联系
        ↓
近景照片 +「盼与您相聚。」
```

## 细节与交互

- 标题只做一次约 1.2 秒入场，照片及时显示；没有等待动画结束才能进入的遮罩。
- 内容默认可见，滚入时轻微位移呈现一次；减少动态偏好下停用动效与平滑滚动。
- 姓名不拆字，双方等重。首屏入口使用一行「时间与地点」，文字和箭头共同点击。
- 图像均保持原比例，递花图不镜像、不遮盖人物。网页新增1600px衍生图以支持430px高密度屏幕，原图不变。
- 离开封面后出现固定导航；正文导航进入可操作区域或弹窗打开时隐藏，避免双入口和遮挡。
- 图片错误保留版面高度并提供主动重试；标题图加载失败显示同文案真实字体。
- 复制成功必须等剪贴板调用完成；失败时呈现可手动复制的完整地址，关闭恢复焦点。
- 正式信息只维护在 `config/wedding.json`；网页短文案在 `config/copy.json`。
- 地址、场地及辅助操作文字为16px，正文邀请18px；农历与电话15px，避免用小字换取精致。按钮明确写“导航到新饭店”“致电新郎”；复制受限时直接提示“请长按下方文字，选择复制。”。
- 窄屏首屏入口文字与箭头上下排，保持日期和姓名完整；照片段增加呼吸空间，移除无信息作用的曲线装饰。

## 超清图片请帖的后续要求

四版统一招手原片。交付至少2160px宽的高清PNG母版与独立分享版，不把1080px图片放大冒充超清；文字以字体或矢量生成，二维码按整数模块重新输出。版面高度由真实排版决定，不裁切人物或下方内容；原始照片4000×6000，后续应直接读取原片。标题素材在实际母版中不得超过其原生分辨率，必要时重新制作适合目标尺寸的字形资产。

微信转发的清晰度和实际扫码必须另验；超清母版不等于平台转发后仍保留原像素。
