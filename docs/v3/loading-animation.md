## 最终行为

- 2026-10-22 用户再次明确：保留早期“解开蝴蝶结、照片从信封出来”的惊喜感，重点改善自然过渡。整条系好的封套向上滑走不再作为最终方向。
- 首屏沿用已确定的封面、原手写标题及日期地点排版。开场为已系好的蝴蝶结，等待时只有两根尾绳轻摆。
- 首屏照片与手写标题真实加载完成后自动启封：右尾先抽、左尾跟随，带耳收回结心，红绳向两侧退开，翻盖，抽出照片，再从同一照片边界展开成正式封面。
- 等待采用定长柔性杆、重力与阻尼。解结从实时尾绳姿态及速度衔接，以连续 SVG 曲线表达抽线；保持整股绳长，带耳减少的长度送入线尾，不突然改变材料硬度，不把闭环直接翻成直线。该效果是二维风格化表达，不宣称三维绳结接触仿真。
- 完整启封为 2400ms：解结 0–770ms、退绳 560–1040ms，翻盖 940–1300ms，抽出照片 1150–1770ms，封面展开 1770–2400ms。解结与退绳重叠，避免两段动作之间停住；展开从相同图像边界不透明接管，消除双层照片交叠。
- 开场从初始 HTML 启动标记起最多占用页面 5000ms，计入入口脚本下载时间。就绪时剩余时间不足 2400ms，则用最多 200ms 淡出；尚未就绪则在 4800ms 开始淡出，5000ms 内交还正文。
- 超时露出内嵌轻量照片、原手写标题和婚礼信息；高清照片到达后渐显，不重新启封。图片失败保留预览和现有“重新加载”入口。
- 减弱动态下停止尾绳和空间运动，资源就绪即可进入正文；后台恢复不补算积压物理帧。离开组件时清理计时器、动画帧、媒体监听和页面滚动限制。
- 指向正文的深链接直接显示目标内容。开场期间正文不可交互，结束后恢复滚动和原有音乐、导航控件。

## 刷新偶发图片失败的体验调整（2026-10-22）

用户真机反馈刷新偶尔提示图片加载失败，并明确要求尽可能自动重试、减少交给用户处理。局域网原地址 12 次刷新（6 次使用缓存、6 次忽略缓存）未复现自然失败；35 个相关图片资源均返回 200、与本地字节一致且完整解码通过。因此尚不能确认真机偶发请求失败的具体原因。

已复现的体验问题：让一次真实首屏图片请求以 `ConnectionReset` 失败，旧组件立即移除高清图并显示失败入口，网络恢复后也不会自行重试。本次按用户要求改变这一行为：

- 每轮首次失败后静默自动重试三次，间隔 400 / 1000 / 2000ms，总请求数最多四次；成功或卸载时取消待执行计时器。
- 重试期间一直保留预览，不显示失败文案，不改变开场五秒截止，也不因迟到的照片重播开场。
- 三次自动重试仍失败时，使用照片底部的小提示“高清照片暂未加载”及 44px 高度的重试按钮，保留完整预览；手动重试开启一轮新的有限重试。
- 不添加无限轮询、额外网络探测或自动切换照片来源。

实际浏览器验证（本地证据 `artifacts/photo-retry-2026-10-22/`）：一次失败后第二次请求成功、连续三次失败后第四次成功，均未出现错误提示；持续失败恰好四次请求后停止，预览仍在，正文可交互。手动重试成功且不重播开场。等待重试时卸载真实 Vue 应用，之后未出现新图片请求。390px 失败提示和恢复画面均已截图核对。

32 项已有测试、类型检查、生产构建及 `git diff --check` 通过。新生产入口 `index-CfLGuyCR.js` 已由原局域网预览服务提供；前文 `index-DqOcQ_OB.js` 的完整动画回放保留其原版本范围。没有改变红绳时序或素材，没有提交、推送或发布。

### 自动重试次数追加调整

按用户要求，自动重试由三次增加至五次，间隔为 400 / 1000 / 2000 / 2000 / 2000ms；每轮包含首次请求在内最多六次。额外两次均间隔两秒，等待期间保留预览，开场仍按原五秒截止交还正文。类型检查与生产构建通过，局域网原地址已确认提供新入口 `index-CNuN6uh4.js`。本次仅调整次数，未重复浏览器故障注入；上文故障注入证据仍对应三次版本。
